# narrative.yaml template

Copy this and edit. **Only these six keys are accepted**; every other section is
generated by code.

```yaml
# ---- Estimand and its population ----
# Say plainly who this number is about. Especially important under IV, where it is not
# the whole population's effect.
estimand: >
  This estimates ... . It answers "...", and says nothing about any specific individual.

# ---- Data quality ----
# Interpret the results; do not restate the table above. Cite specific values by qc: address.
data_quality: >
  Common support is adequate: {{qc:backdoor_overlap.extreme_fraction|.1%}} of the sample
  has a propensity score outside the threshold. After IPW the largest |SMD| fell from
  {{qc:backdoor_covariate_imbalance.max_abs_smd_before|.3f}} to
  {{qc:backdoor_covariate_imbalance.max_abs_smd_after|.3f}}.

# ---- Primary results ----
# The wording must match claim:level. Every number goes through a placeholder.
primary_results: >
  Among {{res:sample.n}} patients, {{res:sample.n_treated}} received treatment.
  The average effect is {{res:primary.ate|+.3f}}, {{lit:95}}% confidence interval
  [{{res:primary.ate_ci_lower|+.3f}}, {{res:primary.ate_ci_upper|+.3f}}], with the
  interval produced by {{res:primary.ate_ci_method}}.
  The median individual effect is {{res:cate.median|+.3f}}, and
  {{res:cate.n_significant_benefit}} patients have an interval lying entirely below zero.

# ---- Sensitivity and refutation ----
# Not implemented. Leave empty; the code notes that an empty section is not a pass.
sensitivity: ""

# ---- Limitations ----
# At minimum, name the untestable assumptions and the limits of extrapolation.
limitations: >
  This analysis rests on ..., which cannot be verified. The sample comes from ...,
  so extrapolation to other settings needs care.

# ---- Post-hoc analyses, if any ----
# Anything decided after seeing the results goes here, never mixed into primary results.
post_hoc: ""
```

## The trap that catches everyone: numbers inside a term

```
Wrong: the outcome is 28-day mortality       <- 28 is a bare number; the render is refused
Right: the outcome is {{lit:28}}-day mortality
```

Same for "{{lit:95}}% confidence interval", "AKI stage {{lit:3}}", "the first
{{lit:24}} hours".

**This is not pedantry.** If numbers inside terms were let through, there would be no
mechanical way to tell "28 days" from "the effect is 0.028" — and the second is
precisely what has to be stopped. The renderer does not read meaning, so it draws one
line and asks you to declare which numbers you did not compute.

The error message tells you exactly what to write:

```
Un-placeheld number(s) in the prose: 28.

  28 -> if this is part of a term (e.g. "28-day mortality"), write {{lit:28}}
```

## Common mistakes

| What you wrote | Why it fails |
|---|---|
| `the outcome is 28-day mortality` | Numbers inside terms need placeholders too — write `{{lit:28}}` |
| `The average effect is about -0.018.` | A bare number; the renderer refuses it |
| `{{res:primary.ate}}` with no format spec | Works, but prints 17 significant digits |
| `{{lit:0.018}}` used as the effect | Smuggling a result through `lit:`; refused |
| adding a `claim_level:` key | That section is code-generated; the model may not write it |
| "dialysis reduced mortality" while the level is `suggestive` | Wording above the level |
